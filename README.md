# 病情說明紀錄改寫（explanation-to-chart）

把醫師口頭向病人說明的內容，忠實整理成客觀、時間序明確、可貼入病歷的繁體中文紀錄。原文沒有的內容一律標成「待確認」，不補寫。

> **English summary.** A Claude skill (also usable as a plain system prompt) that rewrites a physician's informal notes of what was explained to a patient into a structured, neutral Traditional Chinese chart entry, following Taiwan's statutory requirements for disclosure and record keeping. It never invents clinical facts or disclosures. Anything the source text does not contain is flagged for the physician to confirm.

## 為什麼需要這個

門診或查房後，醫師腦中記得的是「我跟他說要做大腸鏡，他說太忙不想做，我有講風險」。寫進病歷時常常只剩「已告知風險，病人拒絕」。這句話留不住任何資訊：接手的同仁看不出說了哪些風險、病人怎麼回應、為什麼拒絕；病人日後調閱自己的病歷，也看不到當時被告知了什麼。

這個 skill 做的是把口語內容拆開、歸位、補上結構，並且明確指出哪些地方你還沒交代。

## 與「防禦性病歷」的差別

有些人會把這類工具叫做防禦性病歷，本專案刻意不這樣定位。防禦性的寫法是為了自保而加上套語、免責句與篇幅；這裡做的相反：只留下實際發生的對話，缺的地方攤開來讓醫師補。把說了什麼、病人怎麼決定寫清楚，受益的是接手的同仁、病人本人，也包含醫師自己。

## 設計立場

1. **病歷的強度來自忠實。** 目標讀者是下一位接手的醫師，以及日後回頭看這份紀錄的任何人，包含病人本人。他們要能重建當時看到什麼、想了什麼、說了什麼、病人決定了什麼。
2. **最大的風險是寫了沒發生的事。** 紀錄不全只是讓舉證變難；登載不實（刑法第 215 條）會讓整份病歷失去可信度。所以這個工具寧可留下「待確認」，也不補上「通常會說」的內容。
3. **結論句沒有用，內容才有用。** 「已告知」「病解完成」「已衛教」都會被換成實際說了什麼，或被標成待確認。

## 它做什麼、不做什麼

| 做 | 不做 |
|---|---|
| 把口語拆成事實單元，分清楚是誰說的、誰看到的 | 新增症狀、陰性發現、數值、劑量、日期 |
| 預設輸出一段文字：說明的推理脈絡，加上對方的回應 | 把「我有講風險」擴寫成具體風險清單 |
| 原文沒有的說明對象與對方回應留空格給醫師填 | 替病人寫出他沒說過的「理解」「同意」「複述」 |
| 替換標籤化、情緒性、保證性用語 | 回填或更改時間 |
| 說「完整版」時改出九段詳細紀錄，逐項標出缺漏並附 12 項自我檢核 | 取代醫師的臨床判斷或法律意見 |

## 輸出長什麼樣子

預設是一段文字，只寫推理脈絡（依據什麼發現，所以做什麼）與對方的回應，不重述病人背景。

輸入：

> 58 歲男性，門診。跟他說大便帶血三個禮拜了，肛門指診摸到內痔，沒摸到腫塊。但他這個年紀又沒做過大腸鏡，不能直接當成痔瘡出血，要排除息肉或腫瘤，所以建議安排大腸鏡。他說最近工作很忙不想做，想先擦藥看看。我有跟他說萬一是腫瘤，拖下去會比較麻煩，他說他知道，還是想先用藥。開了痔瘡藥膏跟軟便劑，兩個禮拜後回診。有交代如果血變多或頭暈要提早回來。

輸出：

```
醫師向病人說明：病人糞便帶血約 3 週，肛門指診觸及內痔、未觸及腫塊；因病人 58 歲且未曾接受大腸鏡，不宜逕以痔瘡出血處理，建議安排大腸鏡以排除息肉或腫瘤，並說明若為腫瘤，延後檢查將延誤診斷與治療。病人表示知道，因近期工作繁忙，決定暫不接受大腸鏡，先以藥物治療。本次開立痔瘡藥膏及軟便劑，2 週後回診；已告知若出血量增加或頭暈應提早回診。
```

「拖下去會比較麻煩」沒有被擴寫成癌症分期的說明，「他說他知道」也沒有被升級成「病人充分理解並複述」。

原文沒有交代對方的回應時，結尾會留空，不會自動寫上「病人表示了解並同意」：

輸入：

> 45 歲女性，急性闌尾炎，CT 確認。跟她說建議今天做腹腔鏡闌尾切除，有講出血、感染、可能轉開腹的風險，也可以先用抗生素治療但復發機會比較高。

輸出：

```
醫師向病人說明：CT 確認為急性闌尾炎，故建議今日接受腹腔鏡闌尾切除；已說明出血、感染及術中可能轉為開腹手術之風險，並說明亦可先以抗生素治療，但復發機會較高。【對方的回應】
```

說「完整版」會改出九段詳細紀錄，逐項標出原文缺漏並附自我檢核，適合手術前說明、拒絕治療這類需要完整留痕的情境。完整的九段範例在 [SKILL.md](skills/explanation-to-chart/SKILL.md) 的示範段落。

## 完整模式的固定架構

| 段落 | 內容 |
|---|---|
| 紀錄屬性 | 記載時間、事件時間、即時或補記、情境、說明對象與在場者、語言 |
| 一、主訴與時間軸 | 起始時間、病程、相關病史 |
| 二、客觀檢查發現 | 理學檢查的陽性與相關陰性發現、檢驗影像 |
| 三、鑑別診斷與排除理由 | 含不可錯過的診斷及其排除依據 |
| 四、臨床判斷與處置 | 為何做、為何不做 |
| 五、已告知事項 | 病情、建議、風險、替代方案（含不處置）、預後 |
| 六、病人或家屬之理解與決定 | 同意、拒絕或暫緩，以及理由 |
| 七、警示症狀與回診衛教 | 具體症狀、出現時的行動與就醫地點 |
| 八、後續追蹤計畫 | 時間、科別、待追蹤報告 |
| 九、共同照護與會診紀錄 | 會診對象與內容 |

之後固定附上「待確認彙整」與「自我檢核」。

另有情境模組：拒絕治療或自動離院、手術或侵入性處置前說明、診斷未明返家、向關係人說明、電話聯繫、不良事件後說明。

## 安裝

### Claude（網頁、桌面、行動 App）

1. 下載本 repo。
2. 把 `skills/explanation-to-chart/` 這個資料夾壓成 ZIP。ZIP 的根目錄必須是 `explanation-to-chart/` 資料夾本身，不能是散落的檔案。
3. 在 Claude 的 Customize > Skills 上傳。介面可能改版，以[官方說明](https://support.claude.com/en/articles/12512180-what-are-skills)為準。

### Claude Code

```bash
git clone https://github.com/odafeng/explanation-to-chart.git
cp -r explanation-to-chart/skills/explanation-to-chart ~/.claude/skills/
```

### 其他模型

`SKILL.md` 去掉最上方的 frontmatter（兩條 `---` 之間的部分）之後就是一份可直接使用的系統提示詞。在其他模型上的表現沒有測試過，尤其是「不補寫」這條規則，請自行驗證。

## 使用

直接貼上病情解釋即可，預設得到一段文字。需要九段詳細紀錄時加一句「完整版」。

```
幫我整理成病情說明紀錄。
（貼上口語內容）
```

完整模式可附上選填欄位，沒附的會列入待確認：科別、情境（門診、急診、住院、電話）、年齡性別、已做的檢查與結果、是否涉及拒絕治療或自動離院、說明對象與在場者、事件時間、即時記載或事後補記。

## 重要限制

- **這是書寫輔助，輸出是草稿。** 負責醫師逐句核對、補完待確認、簽章之後才是病歷。
- **不是法律意見，也不是醫療器材。** 涉及已發生的爭議、申訴、調解或訴訟時，請先找院方法務或風險管理單位。
- **不要貼入可識別病人的資料**（姓名、病歷號、身分證字號、電話、地址）。把病人資料送進任何雲端 AI 服務之前，請先確認符合貴院的資訊安全與個資規範。
- **不竄改事實、不回填時間。** 事後補寫一律標示為補記並寫實際書寫時間；既有紀錄的增刪依醫療法第 68 條辦理。
- **法規脈絡是台灣。** 引用的條文與判決見解以台灣為準，且法規會修正，請以[全國法規資料庫](https://law.moj.gov.tw/)現行條文為準。其他司法管轄區不適用。
- **模型可能出錯。** 即使有規則約束，語言模型仍可能補寫原文沒有的內容。自我檢核第 12 項是模型自評，不能取代你的核對。
